Key Insights

FindingDetail
Fast variables: Protobuf dominates For the fast group (~156 Hz PLC rate), Protobuf captures changes at the full PLC cycle rate (156 /s), while OPC UA is throttled to ~20 /s — a ~8× gap. This means OPC UA drops ~87% of fast-changing data.
Medium variables: 4× advantage Medium-rate variables (~78 Hz) are fully captured by Protobuf but OPC UA only delivers ~20 /s — a ~4× gap. OPC UA appears to have a ~50 ms subscription ceiling regardless of variable rate.
Slow variables: near parity For slow variables (~10 Hz), both protocols deliver virtually identical change rates (10.3–10.4 /s). At low frequencies, OPC UA is not a bottleneck.
OPC UA subscription ceiling OPC UA appears capped at ~20 changes/s per variable, suggesting a minimum subscription interval of ~50 ms. All fast and medium variables cluster around 19.7–19.8 /s regardless of their actual PLC update rate.
Packet-level data Protobuf provides discrete packet-level telemetry (1,563 packets, full timing histograms). OPC UA reports 0 packets — the subscription model doesn't expose packet-level granularity, making jitter analysis impossible.
Type information Protobuf preserves full PLC types (REAL, UDINT, DINT, LREAL, BOOL, etc.). OPC UA reports all types as "?" — type metadata is not available through the subscription interface.
Scalability Protobuf estimates capacity for ~24,048 variables at the current update rate. OPC UA could not provide a safe-variable estimate, suggesting scalability limits are harder to predict.
Integrity Both protocols achieved Perfect integrity — zero dropped packets/updates. Reliability is not a differentiator.

Recommendation

  • Use Protobuf for high-frequency monitoring (>20 Hz), real-time diagnostics, and scenarios requiring packet-level timing data or full type fidelity.
  • OPC UA is acceptable for slow-rate supervisory monitoring (≤10 Hz) where industry-standard interoperability is required and per-variable rates below 20 Hz are sufficient.
  • For mixed workloads, consider a hybrid approach: Protobuf for fast/medium variables, OPC UA for slow/configuration variables where interoperability matters.
